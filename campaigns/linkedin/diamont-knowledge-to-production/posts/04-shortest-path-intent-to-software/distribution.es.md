# Copy de distribución — Pieza 04

Cada vez que un worker de IA entra en un proyecto sin conocimiento preservado, alguien paga para que el proyecto vuelva a ser comprendido.

El pago se realiza en tokens, prompts, explicaciones, exploración del repositorio, suposiciones incorrectas y retrabajo.

Una ventana de contexto mayor no resuelve ese problema. Más material no le indica al worker qué importa, qué continúa vigente, qué puede modificar ni qué resultado será aceptado.

DIAMONT propone otro recorrido:

```text
Intención → conocimiento aplicable → contexto para una capacidad
→ acción delimitada → resultado observable
```

No ahorra tokens comprimiendo prompts hasta hacer desaparecer el significado.

Ahorra tokens reduciendo la cantidad de veces que el significado debe volver a descubrirse.

En la edición 04 de **Knowledge → Production** explico cómo DIAMONT acorta la distancia entre la intención humana y el software implementado, y cómo orienta a un worker hacia un resultado concreto y observable.
